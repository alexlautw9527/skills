# 判定與分流

將目前請求、先前已確認的需求、限制條件、既有系統與程式碼一起判讀，確認使用者是否要做系統設計。使用者直接要求規劃架構、模組、服務、資料流、責任邊界或技術取捨時，屬於系統設計意圖。既有流程已要求開始系統設計時，也屬於系統設計意圖。

只要求解釋、提供建議、審查、研究或實作程式碼而未要求設計時，不套用本 skill。

系統設計意圖成立後，依設計情境選擇符合條件的補充 skill，再進行需求釐清、設計、驗證與交付。每個分支只定義適用條件與要使用的 skill；具體設計規則由被選用的 skill 維護。

## 補充 skill 對照

### 分支：程式碼庫與模組設計

- 適用條件：
  - 工作涉及系統或程式碼庫的結構、模組責任、介面、相依關係或邊界。
  - 工作要決定功能應放在哪裡，或不同模組如何協作。

- 使用 skill：
  - `codebase-design`

- 資訊不足時：
  - 先釐清需求與限制，並探索既有系統的結構、介面與相依關係，再判定是否符合適用條件。

### 分支：可回復性與變更成本

- 適用條件：
  - 工作需要決定資料模型、介面、規格、模組邊界或遷移方式，且之後可能需要修改或撤回。
  - 工作涉及公開 API、不相容資料變更、跨系統相依關係或其他難以完整復原的決策。
  - 需求尚未能列出所有情境，需要定義 invariant 或未知情境的安全行為。

- 使用 skill：
  - `reversibility-engineering-pattern`

- 資訊不足時：
  - 先確認目前決策的使用者、資料生命週期、相依關係與可接受的修改成本，再判定哪些部分需要額外審查。

## 未符合既有分支時

依目前任務與其他適用的 skill 工作。本 skill 不自行補上尚未定義的設計規則，也不猜測尚未建立的分支。
