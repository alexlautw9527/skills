# 判定與分流

將目前請求、先前已確認的需求、規格、設計稿與專案內容一起判讀，確認使用者是否要產出程式變更。使用者直接要求新增、修改、修正或完成程式功能時屬於實作意圖。既有流程已要求開始實作時，也屬於實作意圖。

只要求解釋、提供建議、審查、研究或規劃而未要求實作時，不套用本 skill。

實作意圖成立後，依工作情境選擇符合條件的補充 skill，再進行程式碼探索、修改與驗證。每個分支只定義適用條件與要使用的 skill；具體實作規則由被選用的 skill 維護。

## 補充 skill 對照

### 分支：前端 View 實作

- 適用條件：
  - 工作會改變使用者在前端看見或操作的畫面。
  - 工作涉及頁面、元件、版面、表單、列表、彈窗或其他介面。
  - 工作涉及使用者操作後的互動、畫面狀態、錯誤提示、載入狀態或資料呈現。
  - 工作涉及前端資料取得與畫面呈現之間的程式碼。
  - 需求提到既有前端框架、畫面設計稿或使用者操作流程，且預期結果是程式碼變更。

- 使用 skill：
  - `frontend-testable-view-pattern`

- 資訊不足時：
  - 先探索需求與專案中的相關程式碼，再判定是否符合適用條件。
  - 不要只因為使用者說了「功能」或「開工」就假設它是前端工作。

## 未符合既有分支時

依目前任務與其他適用的 skill 工作。本 skill 不自行補上尚未定義的架構規則，也不猜測尚未建立的分支。
