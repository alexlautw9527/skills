---
name: distill
description: 從已完成的實作、除錯、程式碼審查、驗證工作或使用者對話中，萃取少量可跨工作項目重用的工程知識。適用於降低既有程式碼庫的重複理解成本、避免重複做出已被證據否定的判斷，或判斷已萃取的知識是否值得建立或修改 skill。
---

從完成的工程工作中，只保留足以改變後續判斷或縮短驗證時間的知識。每次保留 0 至 3 條。

不要輸出工作項目摘要、變更紀錄、完整除錯過程、架構文件、工作日誌或脫離具體證據的通用建議。

## 輸入與輸出

輸入可以是已完成的工程工作、使用者提供的對話紀錄，或兩者。只使用目前可讀取的內容；對話被截斷、缺少被引用的修正，或沒有足夠證據時，不補造事件或規則。

基本交付永遠是 0 至 3 條符合本 skill 條件的知識，使用後文 YAML 格式。使用者未要求建立或修改 skill 時，候選知識符合 Skill 升格條件，才提出一項具體建議並詢問是否要進行。這項建議不取代知識輸出。

使用者明確要求把對話或工作經驗整理成 skill 時，先完成候選知識與既有 skill 的檢查，再決定修改既有 skill、建立新 skill，或說明為何不應永久保存。

## 判斷候選知識

依序檢查每個候選內容。任一項不符合時，捨棄它。

### 證據

只採用已驗證的資訊。證據可以來自程式碼、測試結果、可觀察的執行行為、日誌、版本歷史、已確認的介面要求、可重現的操作結果，或使用者明確修正的要求與接受的結果。

不要為了補足候選知識而展開新的調查。需要新調查才能成立的內容，留待該調查完成後再判斷。

### 新的判斷能力

保留會讓後續工作採取不同做法的內容，例如：

- 修正容易產生、但已被證據否定的系統理解。
- 說明不可任意破壞的行為或介面要求。
- 記錄在特定條件下可穩定重現的失敗模式。
- 提供可依訊號快速選擇調查方向的規則。
- 指出成本較低且可信度足夠的驗證入口。

只描述這次修改、只重述一般 API 用法，或只反映個人偏好時，不保留。

### 可重用性

確認該內容至少能帶來一項具體收益：減少重新理解程式碼的時間、避免同類錯誤、更快找到正確處理路徑、更快選擇驗證方法，或更可靠地判斷既有行為是否可變更。

判斷未來工作不會用到時，不保留。不要把可能發生、但尚無證據的邊界情況寫成知識。

## 從對話萃取知識

依序處理已提供的對話內容：

1. 還原使用者原本要完成的任務、限制、最後接受的結果，以及後來被推翻的假設。
2. 找出使用者明確修正、方案被拒絕或證實失敗、改變做法後成功、方案選擇、驗證結果，以及可以停止探索的事件。
3. 對每個事件整理出「事件 → 失敗模式 → 根因 → 可重複使用的知識」。根因無法由對話或已確認結果支持時，捨棄候選。
4. 移除本次任務的檔名、分支名稱、一次性指令、最終答覆措辭與未經驗證的推測。具體資訊本身是長期規格時才保留。

使用者的修正能證明對話中的要求或判斷錯誤，不能單獨證明尚未查證的程式行為。涉及程式行為時，仍要以測試、程式碼、日誌或可重現結果支持結論。

### 最小表述

每條只保留：結論、適用範圍、證據，以及必要時的驗證入口。刪除完整故事、推理紀錄、一次性實作細節與無法影響後續決策的背景。

### 合併既有條目

寫入前搜尋相同領域與適用範圍的既有條目。找到相同結論時，更新該條目的證據、範圍或最後驗證日期。結論已失效時，修正或移除原條目。不要為同一條規則建立多個表述。

## 分類

每條知識只回答一個問題。`type` 沿用詞彙表已定義的 `Model`、`Rules`、`Risks` 與 `Validation` 概念，使用下列最貼近主要結論的值：

- `model`：說明資料、控制流程或元件之間如何運作，回答「系統為什麼會這樣運作」。
- `rule`：描述必須維持的可觀察行為、相容性要求或限制，或指定特定訊號出現時必須採取的處理或調查方向。
- `risk`：連結特定前提、可觀察症狀與已確認原因，說明已知失敗模式或例外情境。
- `validation`：指定可重複執行、能取得或排除證據的操作，回答「如何確認」。

依下列順序選擇 type：

1. 條目主要描述必須維持的要求，或指定出現訊號後必須採取的處理時，使用 `rule`。
2. 條目主要辨識故障的前提、症狀與原因時，使用 `risk`。
3. 條目主要解釋系統機制時，使用 `model`。
4. 條目主要說明如何取得證據時，使用 `validation`。

同一項發現同時包含系統結論與規則或驗證操作時，拆成兩條知識。將系統機制、限制或失敗辨識寫成對應的 `model`、`rule` 或 `risk`；將取得證據的操作另寫為 `validation`。不要讓單一條目同時承載系統結論與規則或驗證操作。

候選超過 3 條時，依下列順序保留：

1. 能避免代價高的錯誤。
2. 能縮短後續理解時間。
3. 能取代耗時的驗證或除錯。
4. 能降低多個程式碼庫之間的理解成本。

## Skill 升格

知識已描述可重複執行的任務流程時，才考慮建立或修改 skill。一條獨立的 `rule` 或 `validation` 通常保留為知識即可。

候選要升格為 skill，需同時符合下列條件：

- 任務有可辨識的觸發情境，以及執行前需要取得的資訊。
- 條件會影響工作順序、方案選擇、驗證方式或停止條件。
- 流程可以交給另一個 agent 重複執行，不需要依賴這次對話的背景。
- 這套流程能避免重複發生的錯誤，或減少後續的探索與返工。
- 規則已在不同任務重複出現、不同事件呈現相同根因、能避免高成本失敗，或已在另一個真實任務驗證有效。

### 先判斷是否修改既有 skill

建立新 skill 前，搜尋任務類型相近的既有 skill，並比較其觸發情境、輸入、交付、判斷流程、驗證與停止條件。

- 既有 skill 已涵蓋任務類型，且新知識只補足其中一個判斷、驗證、停止條件或失敗處理時，修改既有 skill。
- 候選流程的輸入、交付或責任與既有 skill 明顯不同，且沒有既有 skill 可以自然承接時，建立新 skill。
- 候選只對單一 repository、檔案或臨時限制成立，或缺少可觀察的驗證方式時，不建立或修改 skill。

不要只因一次低成本事件建立長期 skill。不要把一個既有 skill 的補充條款拆成新 skill。

### 提出建議並取得同意

使用者沒有明確要求建立或修改 skill 時，符合升格條件的候選只提出一項建議，並詢問是否要進行。建議必須說明：

- 建議修改的既有 skill，或建議建立的 skill 名稱。
- 重複出現的問題、可避免的失敗或可節省的探索。
- 預計新增或修改的觸發情境、流程、驗證與停止條件。
- 既有 skill 為何可以承接，或為何無法承接。

取得同意前，不建立目錄、不修改 skill 檔案，也不將候選視為永久規則。使用者已明確要求建立或修改時，依目前環境適用的 skill 建立與驗證規範執行。

## Output

### 知識

只輸出保留的知識，不加入前言、心得或工作摘要。

```yaml
- type: model | rule | risk | validation
  domain: <相關領域>
  scope: <適用條件與範圍>
  knowledge: <可直接改變後續行動的結論>
  evidence:
    - <可查驗的程式碼位置、測試、日誌或操作結果>
  verify_with:
    - <可重複使用的驗證入口；沒有時省略>
  last_verified: <YYYY-MM-DD>
```

沒有候選內容符合所有條件時，輸出：

```yaml
[]
```

### Skill 建議

使用者未要求建立或修改 skill，但候選符合 Skill 升格條件時，在知識 YAML 後加入下列欄位。不要重述完整對話或知識內容。

```yaml
skill_recommendation:
  action: modify | create
  target: <既有 skill 路徑或建議名稱>
  reason:
    - <重複問題、可避免的失敗或可節省的探索>
  scope: <觸發情境與適用範圍>
  planned_contents:
    - <要加入的判斷、流程、驗證或停止條件>
  existing_skill_assessment: <既有 skill 可以承接或無法承接的原因>
  ask_user: <只詢問是否要建立或修改>
```

沒有符合升格條件的候選時，省略 `skill_recommendation`。

## Stop Conditions

出現下列任一情況時停止：

- 需要新的架構或行為調查才能判斷候選內容。
- 候選內容開始擴張成新的問題清單。
- 開始以推測補足未觀察到的邊界情況。
- 開始記錄實作過程或總結整個工作項目。
- 已保留 3 條知識。
- 沒有候選內容通過證據、新的判斷能力與可重用性的檢查。
- 已決定候選應保留為知識、提出 skill 建議、修改既有 skill、建立新 skill，或不永久保存。
- 需要新的架構、行為或使用者意圖調查，才能判斷是否升格為 skill。

## Validation

輸出須符合下列條件：

- 包含 0 至 3 條知識。
- 每條都有可查驗的證據。
- 每條都寫明可適用的條件或範圍。
- 每條都能改變後續的判斷、調查或驗證行動。
- 移除原本工作項目的名稱與實作細節後，條目仍能被理解與使用。
- 提出或執行 skill 升格時，已說明既有 skill 的搜尋結果、升格條件與保存決策。
