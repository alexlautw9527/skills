# 萃取可重用的實作知識

從完成的工程工作中，只保留足以改變後續判斷或縮短驗證時間的知識。每次保留 0 至 3 條。

不要輸出工作項目摘要、變更紀錄、完整除錯過程、架構文件、工作日誌或脫離具體證據的通用建議。

## 判斷候選知識

依序檢查每個候選內容。任一項不符合時，捨棄它。

### 證據

只採用已驗證的資訊。證據可以來自程式碼、測試結果、可觀察的執行行為、日誌、版本歷史、已確認的介面要求，或可重現的操作結果。

不要為了補足候選知識而展開新的調查。需要新調查才能成立的內容，留待該調查完成後再判斷。

### 新的判斷能力

保留會讓後續工作採取不同做法的內容，例如：

- 修正容易產生、但已被證據否定的系統理解。
- 說明不可任意破壞的行為或介面要求。
- 記錄在特定條件下可穩定重現的失敗模式。
- 提供可依訊號快速選擇調查方向的規則。
- 指出成本較低且可信度足夠的驗證入口。

只描述這次修改、只重述一般 API 用法，或只反映個人偏好時，不保留。

### 可重用性

確認該內容至少能帶來一項具體收益：減少重新理解程式碼的時間、避免同類錯誤、更快找到正確處理路徑、更快選擇驗證方法，或更可靠地判斷既有行為是否可變更。

判斷未來工作不會用到時，不保留。不要把可能發生、但尚無證據的邊界情況寫成知識。

### 最小表述

每條只保留：結論、適用範圍、證據，以及必要時的驗證入口。刪除完整故事、推理紀錄、一次性實作細節與無法影響後續決策的背景。

### 合併既有條目

寫入前搜尋相同領域與適用範圍的既有條目。找到相同結論時，更新該條目的證據、範圍或最後驗證日期。結論已失效時，修正或移除原條目。不要為同一條規則建立多個表述。

## 分類

使用下列最貼近結論的類型：

- `mental-model`：常見理解與實際系統行為不同。
- `invariant`：不可任意改變的可觀察行為或介面要求。
- `failure-pattern`：特定條件下可重現的失敗模式。
- `decision-rule`：出現特定訊號時應採取的判斷或調查順序。
- `verification-path`：可重複使用、能取得可信證據的驗證入口。

候選超過 3 條時，依下列順序保留：

1. 能避免代價高的錯誤。
2. 能縮短後續理解時間。
3. 能取代耗時的驗證或除錯。
4. 能降低多個程式碼庫之間的理解成本。

## 輸出

只輸出保留的知識，不加入前言、心得或工作摘要。

```yaml
- type: mental-model | invariant | failure-pattern | decision-rule | verification-path
  domain: <相關領域>
  scope: <適用條件與範圍>
  knowledge: <可直接改變後續行動的結論>
  evidence:
    - <可查驗的程式碼位置、測試、日誌或操作結果>
  verify_with:
    - <可重複使用的驗證入口；沒有時省略>
  last_verified: <YYYY-MM-DD>
```

沒有候選內容符合所有條件時，輸出：

```yaml
[]
```

## 停止條件

出現下列任一情況時停止：

- 需要新的架構或行為調查才能判斷候選內容。
- 候選內容開始擴張成新的問題清單。
- 開始以推測補足未觀察到的邊界情況。
- 開始記錄實作過程或總結整個工作項目。
- 已保留 3 條知識。
- 沒有候選內容通過證據、新的判斷能力與可重用性的檢查。

## 驗收

輸出須符合下列條件：

- 包含 0 至 3 條知識。
- 每條都有可查驗的證據。
- 每條都寫明可適用的條件或範圍。
- 每條都能改變後續的判斷、調查或驗證行動。
- 移除原本工作項目的名稱與實作細節後，條目仍能被理解與使用。
