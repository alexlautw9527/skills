---
name: distill
description: 從已完成的實作、除錯、程式碼審查或驗證工作中，萃取少量可跨工作項目重用的工程知識。適用於降低既有程式碼庫的重複理解成本，並避免重複做出已被證據否定的判斷。
---

從完成的工程工作中，只保留足以改變後續判斷或縮短驗證時間的知識。每次保留 0 至 3 條。

不要輸出工作項目摘要、變更紀錄、完整除錯過程、架構文件、工作日誌或脫離具體證據的通用建議。

## 判斷候選知識

依序檢查每個候選內容。任一項不符合時，捨棄它。

### 證據

只採用已驗證的資訊。證據可以來自程式碼、測試結果、可觀察的執行行為、日誌、版本歷史、已確認的介面要求，或可重現的操作結果。

不要為了補足候選知識而展開新的調查。需要新調查才能成立的內容，留待該調查完成後再判斷。

### 新的判斷能力

保留會讓後續工作採取不同做法的內容，例如：

- 修正容易產生、但已被證據否定的系統理解。
- 說明不可任意破壞的行為或介面要求。
- 記錄在特定條件下可穩定重現的失敗模式。
- 提供可依訊號快速選擇調查方向的規則。
- 指出成本較低且可信度足夠的驗證入口。

只描述這次修改、只重述一般 API 用法，或只反映個人偏好時，不保留。

### 可重用性

確認該內容至少能帶來一項具體收益：減少重新理解程式碼的時間、避免同類錯誤、更快找到正確處理路徑、更快選擇驗證方法，或更可靠地判斷既有行為是否可變更。

判斷未來工作不會用到時，不保留。不要把可能發生、但尚無證據的邊界情況寫成知識。

### 最小表述

每條只保留：結論、適用範圍、證據，以及必要時的驗證入口。刪除完整故事、推理紀錄、一次性實作細節與無法影響後續決策的背景。

### 合併既有條目

寫入前搜尋相同領域與適用範圍的既有條目。找到相同結論時，更新該條目的證據、範圍或最後驗證日期。結論已失效時，修正或移除原條目。不要為同一條規則建立多個表述。

## 分類

每條知識只回答一個問題，使用下列最貼近主要結論的 type：

- `system-model`：說明資料、控制流程或元件之間如何運作，回答「系統為什麼會這樣運作」。
- `constraint`：描述必須維持的可觀察行為、相容性要求或限制，回答「哪些條件不能被破壞」。
- `failure-signature`：連結特定前提、可觀察症狀與已確認原因，回答「這個現象通常表示什麼」。
- `decision-rule`：指定特定訊號出現時應選擇的處理或調查方向，回答「接下來先做哪一種判斷」。
- `verification-procedure`：指定可重複執行、能取得或排除證據的操作，回答「如何確認」。

依下列順序選擇 type：

1. 條目主要描述必須維持的要求時，使用 `constraint`。
2. 條目主要辨識故障的前提、症狀與原因時，使用 `failure-signature`。
3. 條目主要解釋系統機制時，使用 `system-model`。
4. 條目主要選擇處理或調查方向時，使用 `decision-rule`。
5. 條目主要說明如何取得證據時，使用 `verification-procedure`。

同一項發現同時包含系統結論與操作規則時，拆成兩條知識。將系統機制、限制或失敗辨識寫成對應的事實類型；將處理選擇或查證操作另寫為 `decision-rule` 或 `verification-procedure`。不要讓單一條目同時承載系統結論與操作規則。

候選超過 3 條時，依下列順序保留：

1. 能避免代價高的錯誤。
2. 能縮短後續理解時間。
3. 能取代耗時的驗證或除錯。
4. 能降低多個程式碼庫之間的理解成本。

## 輸出

只輸出保留的知識，不加入前言、心得或工作摘要。

```yaml
- type: system-model | constraint | failure-signature | decision-rule | verification-procedure
  domain: <相關領域>
  scope: <適用條件與範圍>
  knowledge: <可直接改變後續行動的結論>
  evidence:
    - <可查驗的程式碼位置、測試、日誌或操作結果>
  verify_with:
    - <可重複使用的驗證入口；沒有時省略>
  last_verified: <YYYY-MM-DD>
```

沒有候選內容符合所有條件時，輸出：

```yaml
[]
```

## 停止條件

出現下列任一情況時停止：

- 需要新的架構或行為調查才能判斷候選內容。
- 候選內容開始擴張成新的問題清單。
- 開始以推測補足未觀察到的邊界情況。
- 開始記錄實作過程或總結整個工作項目。
- 已保留 3 條知識。
- 沒有候選內容通過證據、新的判斷能力與可重用性的檢查。

## 驗收

輸出須符合下列條件：

- 包含 0 至 3 條知識。
- 每條都有可查驗的證據。
- 每條都寫明可適用的條件或範圍。
- 每條都能改變後續的判斷、調查或驗證行動。
- 移除原本工作項目的名稱與實作細節後，條目仍能被理解與使用。
